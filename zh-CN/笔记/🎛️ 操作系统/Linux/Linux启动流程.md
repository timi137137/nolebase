# Linux启动流程

Linux开机流程其实和其他系统大同小异，区别也只是后面那几步。
## 第一步 - 开机自检

首先通电第一时间就是执行写在主板上的自检程序，也就是俗称的**BIOS**。

而自检程序主要检查CPU、内存、硬盘、PICE设备等是否正常运行，随后开始读取硬盘上主引导记录的`MBR`/`EFI`分区来找到系统引导程序也就是`Bootloader`。

但是近些年**BIOS**已经是称之为传统固件了，现在的程序更多的是**UEFI**新式固件。因此也就对应了上述说的两个不同格式的引导分区：
- BIOS：Legacy（传统）模式，通过读取MBR引导分区启动，固定只有512字节。
- UEFI：新模式，通过读取ESP（EFI）引导分区启动，但支持更大容量GPT分区表的硬盘。

> [!tip] 
> 请注意，在KVM即虚拟环境中，通常对BIOS的支持会好于UEFI。有些时候如果在UEFI模式下出现问题可以试试回退到BIOS，可能就解决了哦。

## 第二步 - 引导程序（Bootloader）

Linux 最主流常见的引导就是**GRUB**引导器了，GRUBE会开始加载内核镜像`vmlinuz`和临时内存磁盘`initramfs`。并且传递内核版本和内核参数，随后解压内核到内存中，将CPU控制权交给内核，任务就结束了。

## 第三步 - 内核初始化

当内核解压后，会开始初始化核心硬件驱动（CPU、内存、硬盘、网卡）但刚启动的时候内核并没驱动可以读取硬盘，所以会有临时内存磁盘`initramfs`作为临时根文件系统来辅助内核加载驱动。

随后内核会找到真正的硬盘分区并挂载根文件系统，卸载掉`initramfs`,开始启动第一个用户态进程。

在近些年的新发行版中，第一个用户态进程是`systemd`，在很久远的时候是`init`。

## 第四步 - 系统初始化

`systemd`在启动后会开始读取配置文件`/etc/systemd/system/default.target`启动对应的目标界面
- `multi-user.traget` - 命令行界面
- `graphical.traget` - 图形界面
随后按照依赖顺序启动服务：网络、SSHD、防火墙、定时任务等，并且进行挂载分区设置主机名等其他任务。

## 第五步 - 启动终端

最后在其他任务都结束后，会启动`getty`来启动终端，至此启动流程结束。
